# Apple 數學考卷對齊契約

本目錄只處理來源清點、課綱對齊、出版社章節與段考範圍模型。第一輪不得生成練習題。

## 1. 權威順序

1. 教育部／國家教育研究院發布的 108 數學領綱
2. 國家教育研究院最新版數學領域課程手冊（用於解釋，不得推翻領綱）
3. 康軒、翰林可驗證的版本目錄與章節資料
4. 考卷卷面、題目內容與答案卷
5. AI 推論（必須標示信心度，不得冒充來源事實）

## 2. 對齊層級

```text
108課綱學習內容代碼
  -> 康軒／翰林版別、學期、章節、小節
  -> 現有 G1～G4 SkillID
  -> 學校與段考範圍
  -> 考卷逐題證據
  -> 題型矩陣（下一階段）
```

- 108 課綱與 SkillID 是多對多關係，不得強迫一對一。
- 現有 SkillID 是執行層穩定識別碼，第一輪不得更名或刪除。
- 官方「學習內容代碼」為逐題對齊主標籤；「學習表現代碼」為輔助標籤。

## 3. 對齊狀態

- `direct`：範圍與年級直接吻合。
- `partial`：只涵蓋官方條目的一部分，或題目內容橫跨多項技能。
- `cross_grade`：內容主要落在其他年級。
- `enrichment`：課綱外的加深加廣內容。
- `uncertain`：證據不足，不可強制歸類。

每筆對齊須保留 `confidence`（`high`／`medium`／`low`）及 `notes`。

## 4. 段考範圍規則

- `期中1 + 期末2` 暫列為 `two_assessment` 制度。
- `期中1 + 期中2 + 期末3` 暫列為 `three_assessment` 制度。
- 上述只是檔名正規化；卷面或題目證據可推翻。
- 「第一次考第 1～3 章」只能是候選範圍，不能寫成固定事實。
- `expectedUnits` 與 `observedUnits` 必須分開。
- 期末卷須判定 `window`、`cumulative` 或 `unknown`，不得一律視為後半冊。
- 超出預期範圍的題目標記 `scope_outlier`，不得硬塞進預期章節。

## 5. 來源與版別

- 考卷涵蓋 108 上至 113 下；出版社資料須保留 `editionFamily`。
- 無法證明不同學年度章節相同時，`editionFamily` 設為 `unknown`。
- 每個出版社章節、小節都要有 `sourceEvidence`；不得只憑記憶補齊。
- 圖表、鐘面、幾何圖與版面切割資訊若 OCR 遺失，標記 `needs_image`。

## 6. 第一輪驗收

- 官方 G1～G4 代碼資料可解析，來源可追溯。
- 出版社章節表的每個 SkillID 都存在於現有課綱檔。
- 考卷題目卷總數為 393，答案卷配對結果有明確統計。
- 批次前處理須有 786 個唯一的 `sourceId + role` 與 786 個唯一輸出路徑；中文 ID 轉檔名時必須附完整 ID 雜湊，不得只用會碰撞的 ASCII slug。
- 考次分布需核對 `期中1`、`期中2`、`期末2`、`期末3`。
- 抽樣 10～15 份後，報告預期範圍、實際範圍、離群題與不確定題。
- 不產生練習題、不改動 `progress.json`、不改既有模板與前端。
