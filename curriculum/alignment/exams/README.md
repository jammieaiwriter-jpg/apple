# TCOOL G1–G4 數學段考盤點與範圍模型

這個目錄是第一輪「來源清點與範圍證據」的產物，不產生練習題，也不修改既有 SkillID、課綱檔或原始 PDF。

## 檔案

- `exam-inventory.json`：393 份題目卷的一卷一筆清單；每筆包含題目／答案 PDF 的路徑、來源 URL、可讀性、頁數、配對結果、學校／學年度／學期／出版社與卷面範圍文字。
- `exam-scope-profiles.json`：依年級、出版社、學期、兩次／三次評量制度與考次聚合的範圍模型。
- `pilot-sample.json`：第一輪逐題對齊候選的 15 份代表性考卷。
- `validation-summary.json`：總數、答案配對與四種考次標籤的機器驗證結果。

## 段考制度判定

`two_assessment` 與 `three_assessment` 是暫時的資料正規化，不是學校評量制度的永久事實。

- 同一「學校、年級、出版社、學年度、學期」來源組含 `期中2` 或 `期末3` 時，該組的 `期中1` 一併歸為 `three_assessment`；這有同校同學期的直接標籤證據。
- 只有 `期中1` 而未找到同校同學期搭配考卷時，暫歸 `two_assessment`，並標記 `assessmentSchemeEvidence: label_provisional_without_companion_exam`。
- `期末2` 為第二次評量的明確檔名；`期中2`、`期末3` 是三次評量的明確檔名。

結果為 354 份暫列兩次評量、39 份暫列三次評量。原始考次標籤的分布不因這個正規化而改變。

## `expectedUnits` 與 `observedUnits`

兩欄刻意分開：

- `observedUnits`：僅由題目卷首頁可文字擷取的「評量範圍／命題範圍」直接轉出的單元序號，並附該證據出現的份數與比例。
- `expectedUnits`：目前保留空陣列。它必須等出版社版本章節表完成、且每一個章節有可追溯來源後，才可由「出版社章節 ↔ 108 課綱」回填；不能用卷面觀察值倒灌成預期事實。

目前 59 個聚合 profile 中有 28 個取得至少一份卷面範圍文字。卷面未寫範圍、掃描待 OCR，或文字擷取不足的 profile 仍保留為 `unknown`，不依「第一次考第 1–3 章」之類的假設補值。

`scopeType` 的規則是：卷面明示「全冊／全學期」才是 `cumulative`；有明示的首次評量範圍或明示非第一單元起訖才是 `window`；其餘為 `unknown`。特別是期末 2 若範圍從單元 1 起，保留 `unknown`，等待出版社全冊單元數和逐題證據確認，不硬判為累積或後半冊。

## 圖像與逐題工作界線

這一輪沒有從 PDF 建立逐題資料。`question.needsImage` 只表示尚未在題目層級判定；後續凡是圖表、鐘面、幾何圖、表格或 OCR 遺失版面資訊的題目，必須標為 `needs_image`。`scope_outlier` 也要等逐題單元對齊後才標記，不能只憑整卷範圍推定。

## 第一輪樣本

`pilot-sample.json` 共 15 份，涵蓋：G1–G4、康軒與翰林、上下學期、兩次與三次制度，以及三次制度的第 1／2／3 次。優先使用題目卷文字可讀且答案已配對者；包含一份掃描卷作為 OCR／圖像工作流的驗證樣本。
